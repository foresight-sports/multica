# Slack support intake

Workspace administrators configure this under Settings → Slack → Channel workflows. The initial workflow is support diagnosis; each channel has an escalation person and deadline. The workspace Intake Coordinator automatically owns routing and selects the required agents and audience. Shared audience wording is managed under Instance → General. The communications agent uses its normal execution profile, so its model can be changed independently of Sammy and the coordinator.

For FS App, first test FS Caddie in an explicitly selected private channel, with Kody Peterson for escalation. Do not enable `#foresight-app-bugs-and-support` until production use is explicitly requested. The coordinator selects Sammy or other appropriate specialists and a communications writer when useful; none are selected in the Slack connection. Select actual channel/member IDs through the directory; names alone are not routing keys.

1. The host must set a persistent base64-encoded 32-byte `MULTICA_SLACK_SECRET_KEY`. Preserve it with the protected deployment environment; rotating it without re-encrypting saved installations breaks their credentials.
2. Create/install the FS Caddie Slack app with Socket Mode enabled and an app-level token with `connections:write`. Connect its bot token and app token through the existing Slack app connection UI; never place tokens in agent instructions or issue comments.
3. Grant bot scopes `chat:write`, `reactions:write`, `channels:read`, `channels:history`, `groups:read`, `groups:history`, `users:read`, and `files:read` for the channels/files you intend to use. Subscribe to `message.channels` and, for private channels, `message.groups`. Existing mention/direct-chat use cases may additionally need their existing scopes/events. Reinstall the app after scope changes and invite it to the monitored channel.
4. Save the channel workflow. Saving provisions the explicitly named FS Caddie non-login workspace member. It has its own identity, with no copied human integration credentials. Removing its membership stops intake processing. It can invoke only agents its workspace grants allow. Cross-workspace requests require explicit links and membership there too.
5. Enable the workflow when ready. Only new top-level human messages create investigations. Replies on tracked threads add evidence and wake the coordinator; old untracked threads, bot messages and edit/delete events do not create issues. Disabling stops processing and outbound replies.

The coordinator determines the audience and required expertise, delegates when useful, reviews evidence and decides disposition. Missing expertise or an unknown route requires clarification or escalation, not a guessed substitute. Only the running coordinator may submit `multica issue support-reply`, and substantive replies wait for any delegated work on the issue to finish. Low confidence and timeouts produce an escalation mentioning the configured person. Confirmed defects create backlog issues without dispatching implementation. Jira is not required for investigation or backlog creation; PRs retain their normal policy. FS Caddie has no personal Jira connection and cannot borrow one.

Replies use the original thread with a small Multica issue reference. A robot reaction marks processing. Inbound events are persisted before Socket Mode acknowledgement and deduplicated. An uncertain Slack POST is reconciled by receipt metadata; it is never blindly repeated. Settings show delivery errors for operator investigation. Disabling does not cancel already running diagnosis tasks or undo an external post already in flight. Confidence is an agent assessment checked against completed evidence gathering, not a guarantee that the conclusion is correct.

No live Slack messages are sent by automated tests. Handler integration tests use the isolated policy-test database and provider tests use an HTTP stub.
